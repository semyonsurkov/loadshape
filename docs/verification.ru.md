# Воспроизводимая проверка playground

[English](verification.md) · [Русский](verification.ru.md)

## Card: контент, скелетон, контент

Проверка проходит существующий `/stands/card` через его элементы управления. Она проверяет
совместную работу настоящего `Skeleton.Root`, CSS playground и фокуса в браузере. Используются
встроенный демонстрационный профиль и изображения в data URL; бэкенд, авторизация, MSW и внешние
учётные записи не требуются. Запросы данных и действие Follow этим сценарием не проверяются.

Из корня репозитория с закреплённой версией pnpm и установленными зависимостями workspace:

```sh
agent-browser --version
pnpm --filter playground verify:card
```

Нужны CLI `agent-browser` и поддерживаемый им Chrome/Chromium. Команда сама не устанавливает
зависимости и браузер. Если CLI отсутствует, используйте
[официальную инструкцию установки](https://agent-browser.dev/installation). Проверка загружает
существующий конфиг Vite с исходниками библиотеки, отдельная сборка и опубликованный пакет
не нужны. Vite слушает только loopback и получает собственный свободный порт; чужие серверы
не используются и не останавливаются. Для каждого запуска создаётся отдельная браузерная
сессия без личного профиля.

Браузер открывает Card с viewport 1440 × 1000, выбирает светлую тему, ширину предпросмотра
375 px и длинный текст, затем проходит один сценарий:

1. Нажимает **Show content**. Проверяет фактический viewport и ширину предпросмотра, видимый текст
   профиля, декодирование изображений и возможность фокуса на Follow.
2. Нажимает **Show loading**. Проверяет `data-skeleton="loading"`, `inert`, `aria-busy` на внешнем
   контейнере и прозрачный текст. Дожидается нарисованной заглушки и проверяет, что Follow
   не получает фокус. Сравнивает координаты корня, карточки, изображений, заголовка, описания,
   статистики и кнопки с загруженным состоянием, допуская до 0,5 CSS px по координате или размеру.
3. Снова нажимает **Show content**. Проверяет восстановление текста, фокуса и геометрии,
   отсутствие необработанных ошибок браузера. React state и атрибуты загрузки напрямую не меняются.

Команда выводит `PASSED` или `FAILED`, путь отчёта и возвращает ненулевой код при провале
проверки или очистки. Каждый запуск сохраняет доказательства в новом каталоге
`.scratch/verification/card/<run>/`:

- `report.json` содержит фактические измерения, результаты команд, ограничения и статус очистки.
- `content.png`, `loading.png`, `recovered.png` показывают три наблюдавшихся состояния.
- При ошибке браузерного этапа предпринимается попытка сохранить `failure.png`.

Верификатор закрывает только свою браузерную сессию и свой экземпляр Vite, включая провал
проверки. Доказательства после очистки сохраняются, URL из отчёта перестаёт работать.
Для самостоятельного просмотра того же сценария на отдельном сервере:

```sh
pnpm dev --host 127.0.0.1 --port 4187 --strictPort
```

Откройте `http://127.0.0.1:4187/stands/card` и повторите действия выше. Занятый порт вызывает
ошибку; остановите собственный предыдущий сервер или выберите другой порт. После просмотра
остановите этот вручную запущенный сервер через Ctrl+C.

## Границы и поддержка

Это один воспроизводимый сценарий playground. Матрица React 18, WebKit, остальные стенды,
настоящие запросы данных, точный тайминг 150 ms, пиксельное совпадение и субъективное качество
интерфейса им не проверяются. Существующие unit, SSR и browser suites описаны в
[документации тестов](testing.ru.md). Автоматический результат не заменяет пользовательскую приёмку.

Поддерживайте имена элементов управления и DOM-проверки в
`apps/playground/scripts/verify-card.mjs` в соответствии с настоящим стендом Card. При ошибке
сохраните отчёт до разбора причины; не ослабляйте сценарий ради зелёного результата. Состояние
задачи dev-flow хранится отдельно в `.scratch/dev-flow/<task>/state.md`, эта страница описывает
поддерживаемый сценарий.
