# Тесты

[English](testing.md) · [Русский](testing.ru.md)

Постоянный набор проверяет библиотеку на четырёх уровнях. HTTP-вызовов в библиотеке нет, поэтому
MSW не применяется, а отдельного E2E-приложения нет: границу реального браузера закрывает Browser
Mode.

## Уровни

| Уровень            | Что проверяется                                                                                       | Инструмент                                         |
| ------------------ | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| Static types       | Публичные пропсы, ref, совместимость с React 18 и 19                                                  | `tsc --noEmit`                                     |
| Unit и integration | Публичные экспорты, состояния компонентов, слияние пропсов, обработчики, ref, адаптер TanStack Router | Vitest, jsdom, Testing Library                     |
| SSR                | Сериализация `inert`, атрибутов состояния и подписи Spinner; отсутствие предупреждений React          | `react-dom/server`                                 |
| Browser            | Реальный `inert`, фокус, геометрия на ширинах 375, 768 и 1440, видимость Static, гидратация           | Vitest Browser Mode, Playwright, Chromium и WebKit |

Юнит-тесты и интеграционные тесты лежат рядом с исходниками как `*.test.tsx`. SSR-файлы называются
`*.ssr.test.tsx`, браузерные `*.browser.test.tsx`; проекты Vitest разделены по этим шаблонам.

Браузерные тесты проверяют поведение, которое jsdom не воспроизводит: `inert` не пускает фокус,
заглушка не меняет координаты детей, Static остаётся видимым, серверная разметка гидратируется без
расхождений. Ширина контейнера в проверке геометрии равна ширине вьюпорта минус отступ, поэтому
текст на 375, 768 и 1440 px переносится по-разному и сравнение идёт на разных раскладках. Палитра,
отступы и тайминги анимаций не проверяются; из вычисленных стилей читается только прозрачность
текста, по которой видно, что Static остаётся видимым.

## Команды

```sh
pnpm --filter loadshape test          # unit, integration и SSR
pnpm --filter loadshape test:browser  # Chromium и WebKit
pnpm --filter loadshape test:all      # оба набора
pnpm --filter loadshape typecheck
```

Первый браузерный запуск требует установленных браузеров Playwright:

```sh
pnpm --filter loadshape exec playwright install chromium webkit
```

## Матрица React

Основной локальный прогон идёт на React 19 из devDependencies. GitHub Actions в
`.github/workflows/ci.yml` запускает oxlint, проверку Prettier, typecheck библиотеки, unit, SSR,
браузерные тесты и сборку библиотеки дважды: на React 19.3.0 и на React 18.3.1 с соответствующими
`@types/react`. Версия 18 устанавливается в отдельной задаче матрицы, поэтому npm-алиасы и
смешивание двух React в одном процессе не нужны. Typecheck и сборка всего воркспейса с playground
идут только в задаче React 19: playground видит исходники библиотеки через условие `source`, и
рядом с React 18 из пакета в его сборку попали бы две версии React.

Локальная проверка React 18 без изменения рабочего `package.json` выполняется в отдельной копии
репозитория с override `react` и `react-dom` на 18.3.1, `@types/react` на 18.3.31 и `@types/react-dom`
на 18.3.7.

Один тест проверяет очистку, которую React 19 вызывает у колбэк-ref вместо передачи `null`. На
React 18 такого механизма нет, поэтому тест помечен `test.runIf` и в этой задаче матрицы
пропускается; освобождение ref на 18 закрывает общий тест с передачей `null`. Остальные тесты
одинаковы для обеих версий.
