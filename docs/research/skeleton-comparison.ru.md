# Сравнение скелетонов на карточке

[English](skeleton-comparison.md) · [Русский](skeleton-comparison.ru.md)

Дата проверки: 2026-10-31. Сравниваются опубликованные loadshape 0.2.5,
auto-skeleton-react 1.0.5 и @shimmer-from-structure/react 2.4.6 с core 2.4.6.

## Вывод

У loadshape есть проверяемые отличия: существующее поддерево сохраняется при переключении
загрузки, для заглушки не нужна вторая копия компонента или JavaScript-измерение DOM,
а `inert` блокирует фокус. В проверенной карточке многострочный текст остаётся отдельными
полосами, которые следуют переносам строк. Это позволяет объяснить выбор библиотеки
конкретным поведением.

Генерация заглушки из настоящего компонента уже есть у обоих аналогов. Shimmer поддерживает
пересчёт размеров, `templateProps`, провайдер конфигурации и адаптеры других фреймворков.
Сам по себе автоматический скелетон не является уникальным преимуществом loadshape.

## Метод

В отдельном локальном Vite-стенде все три библиотеки оборачивают один и тот же настоящий
`ProfileCard` из playground с одинаковыми PROFILE-данными и CSS. После карточки добавлено
неконтролируемое поле Local draft, чтобы проверить сохранение DOM-состояния. Обёртка над
карточкой считает монтирования и размонтирования через `useEffect`.

Chromium запущен через agent-browser 0.41.0, React 19.3.0, viewport 900 × 1000, без StrictMode.
Используются опубликованные сборки аналогов и локальная dist-сборка loadshape 0.2.5,
соответствующая опубликованному пакету. Зависимости проекта и production-код не менялись.
Внешние пакеты скачаны из npm без установки и lifecycle-скриптов.

Для каждого варианта открывается новая страница: вводится `draft retained`, включается
загрузка, проверяется программный фокус, ширина уменьшается с 375 до 280 px, описание
удлиняется втрое, добавляется текстовый элемент, затем возвращается контент. Данные внутри
каждого перехода loading не меняются до отдельного шага изменения текста. Перед измерениями
ожидаются шрифты и изображения, после действий даются 400 мс на эффекты и переходы.
Цвета и анимации библиотек оставлены стандартными; внешний вид по вкусу не ранжируется.

## Наблюдения в браузере

| Проверка                                           | loadshape 0.2.5                     | auto-skeleton-react 1.0.5                      | Shimmer React 2.4.6              |
| -------------------------------------------------- | ----------------------------------- | ---------------------------------------------- | -------------------------------- |
| Живых экземпляров карточки при loading             | 1                                   | 2                                              | 1                                |
| Монтирования / размонтирования после полного цикла | 1 / 0                               | 2 / 1                                          | 3 / 2                            |
| Значение Local draft после цикла                   | `draft retained`                    | `draft retained`                               | `initial`, введённое потеряно    |
| Фокус на поле во время loading                     | Заблокирован                        | Принимают оба поля                             | Принимает скрытое поле           |
| Заглушка после сужения до 280 px                   | Следует новой ширине                | Сохраняет прежнюю ширину, выходит за контейнер | Следует новой ширине             |
| Удлинение текста и добавление элемента при loading | Отражаются в заглушке               | Заглушка остаётся от прежней разметки          | Отражаются в заглушке            |
| Длинное описание                                   | Полосы по строкам, последняя короче | Полосы по прежнему короткому описанию          | Один прямоугольник на весь абзац |
| Необработанные ошибки браузера                     | 0                                   | 0                                              | 0                                |

Это наблюдения одного сценария, а не оценка всех применений. Для auto-skeleton использовался
стабильный стандартный config; изменение config может инициировать новый пересчёт.
Поле добавлено специально для проверки состояния и не является частью исходной карточки.
Проверка фокуса использует `element.focus()`, полноценный проход скринридером не проводился.

Во всех трёх вариантах исходная карточка сохранила размер 375 × 388,875 px при первом
переключении loaded → loading. Это не означает точности сгенерированной заглушки:
auto-skeleton держит настоящий контент в потоке даже тогда, когда поверх него лежит
заглушка с устаревшими размерами. CLS и производительность не измерялись.

## Что объясняют исходники

**loadshape** добавляет к существующему корню `data-skeleton="loading"` и `inert`.
CSS меняет отрисовку текста и медиа, используя реальную раскладку. У Root нет измерений DOM,
ResizeObserver или дополнительных копий children. Мерцание скелетона включается только при
`prefers-reduced-motion: no-preference`; задержка по умолчанию составляет 150 мс.
`aria-busy` должен поставить потребитель на контейнер снаружи inert-корня.
[Root](https://github.com/semyonsurkov/loadshape/blob/9a0afb8c2a0fce242cbfd97d68f7b8bf73e5de53/packages/loadshape/src/skeleton/Root.tsx),
[CSS](https://github.com/semyonsurkov/loadshape/blob/9a0afb8c2a0fce242cbfd97d68f7b8bf73e5de53/packages/loadshape/src/styles.css).

**AutoSkeleton** оставляет основное дерево и монтирует второе для измерений. Через
requestAnimationFrame собирает DOM-геометрию и строит отдельное дерево заглушки. Эффект
зависит от loading/config, автоматического наблюдения за resize нет. Прозрачность скрывает
контент визуально, но `inert` и `aria-hidden` не устанавливаются. Это согласуется с
дублированием эффектов, устаревшей геометрией и доступным фокусом в эксперименте.
[AutoSkeleton.tsx, опубликованный gitHead](https://github.com/ShanukJ/auto-skeleton/blob/b2fadacd31413670177243fde0c90a42cf4fc6bd/src/AutoSkeleton.tsx),
[renderer](https://github.com/ShanukJ/auto-skeleton/blob/b2fadacd31413670177243fde0c90a42cf4fc6bd/src/skeleton-renderer.tsx).

**Shimmer** измеряет единственное дерево через useLayoutEffect и ResizeObserver и рисует
абсолютно позиционированные плашки. При loading children находятся внутри дополнительных div,
а после загрузки возвращаются во fragment; эксперимент подтвердил remount и потерю значения.
На скрытом дереве стоит `aria-hidden`, но нет `inert`. В проверенной версии нет автоматического
учёта reduced motion. `templateProps` клонирует только первый React-child.
[React adapter](https://github.com/darula-hpp/shimmer-from-structure/blob/64cda5378c304ecf497d58db2f399d3df4968207/packages/react/src/Shimmer.tsx),
[ResizeObserver](https://github.com/darula-hpp/shimmer-from-structure/blob/64cda5378c304ecf497d58db2f399d3df4968207/packages/core/src/createResizeObserver.ts),
[extractor](https://github.com/darula-hpp/shimmer-from-structure/blob/64cda5378c304ecf497d58db2f399d3df4968207/packages/core/src/extractElementInfo.ts).

У обоих аналогов геометрия плашек появляется после клиентского измерения. У loadshape
сервер может сразу вернуть атрибуты загрузки, а CSS применится при отрисовке браузером.
Это вывод из исходников, отдельный сравнительный прогон SSR/hydration здесь не выполнялся;
ошибки гидратации аналогам не приписываются.

## Ограничения loadshape и выбор

Все три решения нуждаются в содержимом, которое можно отрендерить: данные-заглушки,
типичная длина строк и количество элементов остаются ответственностью приложения.
Геометрия placeholder и настоящих данных может различаться, поэтому обещать нулевой CLS
на неизвестных данных нельзя.

Loadshape использует современный CSS, включая `:has()`, `color-mix()`, маски и текстовые
декорации. У сложных текстовых конструкций есть ограничения Static, изображения требуют
зарезервированных размеров, неоформленные поля могут менять геометрию в WebKit. SVG,
фоны и рамки контейнеров обычно остаются настоящими. CSS-селекторы также требуют работы
браузера; отсутствие JS-измерений не доказывает меньшую суммарную стоимость рендеринга.
Видимый Static внутри inert-корня тоже остаётся недоступным для взаимодействия.
[Контракт и ограничения](https://github.com/semyonsurkov/loadshape/blob/9a0afb8c2a0fce242cbfd97d68f7b8bf73e5de53/packages/loadshape/README.md).

Loadshape подходит, когда требуется сохранить экземпляр компонента и локальное состояние,
получить полосы настоящего текста и блокировать фокус во время загрузки. Shimmer стоит
рассматривать, когда важны его API конфигурации, измеряемые плашки и адаптеры других
фреймворков, учитывая проверенное поведение React-адаптера. AutoSkeleton в проверенной версии
требует дополнительных мер для фокуса, повторных эффектов и изменяемой геометрии.
Это выбор по требованиям; универсального победителя этот эксперимент не устанавливает.

Проверяемая формулировка для loadshape: «Скелетоны из существующего React-компонента
через CSS, с сохранением его экземпляра и блокировкой фокуса при загрузке».
Обещания превосходства по скорости, размеру бандла или совместимости требуют отдельных замеров.

## Воспроизведение и доказательства

Локальные материалы лежат в `.scratch/research/skeleton-comparison/`: `versions.json`,
`competitors.md`, `fixture.jsx`, `fixture.css`, `harness.mjs`, `probe.mjs`,
`browser-results.json` и скриншоты каждого варианта. Harness использует уже установленные
зависимости loadshape, импортирует настоящий ProfileCard и скачанные dist аналогов.
Запуск из корня: `node .scratch/research/skeleton-comparison/harness.mjs`, затем адрес из
вывода нужно подставить в probe.mjs вместо зафиксированного экспериментального порта и
запустить `node .scratch/research/skeleton-comparison/probe.mjs`.

Эти материалы временные и не входят в распространяемый пакет или git. Это воспроизводимость
локального эксперимента, публичный независимый benchmark не подготовлен. Сервер и собственная
сессия браузера после проверки закрыты. Версии аналогов закреплены по
[npm auto-skeleton-react 1.0.5](https://registry.npmjs.org/auto-skeleton-react/1.0.5) и
[npm Shimmer React 2.4.6](https://registry.npmjs.org/@shimmer-from-structure%2freact/2.4.6);
актуальный main может отличаться от опубликованного пакета.
