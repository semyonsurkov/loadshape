# 0013. Приостанавливать мерцание вне экрана общим IntersectionObserver

[English](0013-pause-offscreen-skeleton-shimmer.md) · [Русский](0013-pause-offscreen-skeleton-shimmer.ru.md)

- Статус: accepted
- Дата: 2026-10-31
- Решали: Semyon Surkov согласовал прототип и реализацию после браузерного аудита
- Задача: [issue #1](https://github.com/semyonsurkov/loadshape/issues/1)

## Контекст

В синтетическом Chromium-стенде 300 групп по пять загружающихся Root поддерживали 5400 анимаций,
хотя видны были только две группы. Изолированный прототип снизил медианную стоимость пересчёта
стилей с 497 до 14 мс за секунду, приостанавливая невидимое мерцание. Это стоимость постоянной
анимации на dev-стенде; production INP и другие устройства этим замером не оценивались.

## Рассмотренные варианты

- **Оставить CSS-анимации везде:** проще всего, но сохраняет измеренную нагрузку вне экрана.
- **Требовать виртуализацию от приложения:** уменьшает DOM, но остаётся отдельной задачей
  приложения и автоматически не помогает существующим подключениям Root.
- **Применить content-visibility или containment:** может менять размеры и позиционирование,
  нарушая существующий контракт геометрии.
- **Опрос прокрутки и размеров или измерение каждого листа:** добавляет обработчики, таймеры
  и чтение геометрии.
- **Общий IntersectionObserver для загружающихся Root:** асинхронное отслеживание видимости
  средствами браузера, небольшой клиентский жизненный цикл, без новых зависимостей и пропсов.
  Выбран этот вариант.

## Решение

Пока есть загружающиеся Root, использовать один IntersectionObserver на документ-владелец.
Клиентский эффект регистрирует отрисованный DOM-элемент; стабильный внутренний ref отслеживает
его замену, сохраняя подключение refs приложения при смене loading. Callback наблюдателя меняет
внутреннюю переменную `--_skeleton_animation_state` напрямую, без React state и второй копии детей.

Переменная управляет только мерцанием скелетона. Задержка появления продолжает идти, поэтому
прокрутка её не запускает заново. Видимый корень возобновляет анимацию, невидимый ставит на паузу.
У каждого наблюдаемого корня собственное явное состояние, чтобы вложенный загружающийся Root
не наследовал решение о видимости предка.

Серверный рендер не обращается к браузерным API и не добавляет состояние видимости. При отсутствии
IntersectionObserver сохраняется прежний CSS. Нулевой бокс, в том числе у display:contents,
сохраняет анимацию, поскольку бокс корня не определяет видимость детей. Подключение только через
CSS-атрибуты не меняется. После загрузки, замены элемента и размонтирования наблюдение снимается;
после последнего корня наблюдатель отключается.

## Последствия

Публичные пропсы, атрибуты, CSS-переменные, inert и геометрия сохраняются. Внутренний ref
объединяется с render/forwarded refs через существующую утилиту. К CSS-отрисовке добавляется
небольшой клиентский жизненный цикл наблюдателя. Видимость определяется боксом корня, без обхода
всех потомков; callback асинхронный, поэтому начальная CSS-анимация может идти до первого ответа.

Проверяются прокрутка и возобновление, вложенные корни и корни без бокса, StrictMode, refs,
очистка, SSR/hydration, отсутствие API и React 18/19. Новые постоянные тесты в этом инкременте
не поручались; используются существующие наборы и изолированные браузерные проверки. Выигрыш
для произвольных экранов, production JavaScript, GPU и неизмеренных платформ не заявляется.

Источники: [IntersectionObserver](https://developer.mozilla.org/en-US/docs/Web/API/IntersectionObserver),
[жизненный цикл эффекта React](https://react.dev/reference/react/useEffect).
