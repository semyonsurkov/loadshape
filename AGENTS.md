# loadshape

Публичная npm-библиотека состояний загрузки для React в духе Base UI: скелетон, который строится из
самого компонента и поэтому совпадает с контентом по геометрии, спиннер и полоса перехода между
страницами. Внешнего вида у библиотеки нет, он приходит из токенов проекта через CSS-переменные.

Общие стандарты разработки — в глобальном `AGENTS.md`. Ниже только специфика проекта.

## Стек

- Монорепо на pnpm workspaces (`packageManager` закреплён в корневом `package.json`):
  `packages/loadshape` — библиотека, `apps/playground` — стенды
- Библиотека: TypeScript, React 19 как peer, без runtime-зависимостей, сборка tsdown, ESM с типами,
  стили одним файлом `loadshape/styles.css` в `@layer loadshape`, селекторы по data-атрибутам
- Точки входа: `loadshape`, `loadshape/styles.css`, `loadshape/tanstack-router`
- Playground: Vite, React 19, TanStack Router, CSS Modules на токенах из
  `~/.agents/standards/tokens.md`, `agentation` в dev
- Линтер oxlint, форматтер Prettier
- Публикация: npm, MIT, версии и changelog через changesets; основной удалённый репозиторий GitHub
- Скилл для агента: `skills/loadshape/SKILL.md`, ставится через `npx skills add`

## Документация

- `blueprint/` — локальная страница проекта (схема, roadmap) поверх файлов проекта, вкладки в
  `blueprint/blueprint.json`, запуск `blueprint`, без CLI `python3 blueprint/serve.py`
- `docs/adr/` — архитектурные решения и отвергнутые варианты, формат в `~/.agents/standards/adr.md`
- `docs/agents/domain.md` — язык предметной области, читается перед работой с механизмом заглушки
- `docs/<подсистема>.md` — описание живущих частей библиотеки

## Процесс

- Ведётся через: цепочку Мэта Покока (`grill-with-docs` → `to-spec` → `to-tickets` → `implement` →
  `code-review`), плагин включён в `.claude/settings.json`
- Порядок работы: `docs/roadmap.md`, активен один этап и одна спека; идеи вне этапа одной строкой в
  `IDEAS.md`
- Трекер задач: локальный markdown до появления репозитория на GitHub, затем GitHub Issues; детали
  в `docs/agents/issue-tracker.md`
- В теле спеки каждого этапа держится раздел «Что не сработало»: тупики и отвергнутые подходы с
  причиной отказа, чтобы следующая сессия не шла туда снова

## Правила проекта

- Значимое решение с альтернативами фиксируется ADR в тот же заход, что и код
- Публичный API (имена компонентов, пропсов, data-атрибутов и CSS-переменных) меняется только через
  ADR и запись в changeset: это контракт с чужими проектами
- Библиотека не задаёт цветов, радиусов и размеров: только механизм и переменные с безопасными
  значениями по умолчанию
- В `packages/loadshape` не появляется runtime-зависимостей, кроме React как peer
- Удалённые репозитории и публикация в npm только по явной команде пользователя
